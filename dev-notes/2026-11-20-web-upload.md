# 网页图片上传

## 范围与实现

在既有 Qwen3.5 图文后端之上接通网页上传，无模型数值路径或服务依赖变化。web/app.js 提供选择、拖放、预览、移除及失败后恢复附件；web/attachments.mjs 统一校验与 API 内容转换。纯文本仍使用字符串，图片转成内联 image_url 与文本数组。

能力查询控制上传入口；当前会话累计最多4张、总压缩大小8MiB，含历史图片。仅PNG/JPEG，非空，尺寸每边4096、总像素1600万、长宽比200，与后端限制一致。服务仍独立验证。只传图片使用默认描述问题。切换/新建会话清空待发送附件，读取文件时禁止切换；历史图片保留在对应消息中。

web/storage.mjs 使用 IndexedDB 保存会话和图片，读取旧 localStorage 文本历史，避免图片突破 localStorage 容量。保存失败显示提示；不提供跨浏览器同步，用户清理站点数据将失去历史。未发送附件只保存在当前页面内存。

## 实际验证

- Node 纯逻辑测试通过：格式拒绝、能力限制、历史/待发送累计数量及字节限制、图文 API 转换、拒绝远端 URL。
- app.js 模块语法检查通过。
- 浏览器真实文件选择：上传合成红色PNG，缩略图可见，提问“主要是什么颜色？只回答颜色。”，模型输出“红色”，86输入token / 1输出token。
- 刷新页面后，图片、问题、答案和每轮指标均恢复，原文本会话保留。
- 该浏览器单轮 TTFT 51ms，仅为功能冒烟数据；无预热/重复控制，不用作性能对比。

验证服务为 p8_hzy 的 Qwen3.5-0.8B、FP32单卡、上下文2048、无KV Cache。未对本次仅前端改动重新运行模型logits对照，沿用先前后端验证。移动设备和所有浏览器的拖放行为尚未逐一覆盖；暂不支持音频/视频/其他文件。

自动测试：`node tests/web/test_attachments.mjs`，Node只用于开发检查，不进入推理运行链路。本次统一整理并交付此前模型、原生服务、静态图片后端及网页上传工作，保留原始数值验证与sanitizer证据。
