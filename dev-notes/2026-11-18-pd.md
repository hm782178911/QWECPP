# 2026-11-18：同机双卡 PD 分离

`--parallel pd --devices 0,1` 将两张卡分别用于 Prefill 和 Decode。两卡均加载完整 Qwen3 权重，聊天自动启用 KV Cache。每轮 reset 后由首卡计算 prompt 和首 token；下一次前向才逐层交接有效 K/V。后续使用 Decode 卡缓存，沿用精确 token 前缀与 RoPE 位置。复制或前向执行失败后清空逻辑前缀，缓存分配可复用。每轮只输出一个 token 或直接 EOS 时无需交接。

交接复用 `backend/cuda/transfer` 的 P2P 数据校验和固定页主机回退。FP32 逻辑 payload 为 2 × 层数 × prompt token 数 × KV heads × head_dim × 4 字节。调试输出区分 Prefill、KV 传输调用和 Decode，Decode 时间包含首次目标缓存分配。TTFT 在交接前计入，TPOT 含首个间隔中的交接成本。

## 实际验证

- 双 RTX PRO 6000 Blackwell Max-Q、Qwen3-0.6B。构建和 4 项 CTest 通过。
- `test_kv_cache MODEL pd` 和 `pd-host` 与单卡缓存基线的末位置 logits 和 argmax 一致。所测最大及平均绝对误差均为 0。两个 prompt token 交接 458752 字节，自动路由 56 次 P2P，强制中转 56 次 host。
- 覆盖首次交接、持续 Decode、前缀改变、reset。单卡、PP、TP 原缓存数值回归通过。
- `python3 tests/models/test_kv_chat.py` 验证三轮生成含 `/clear`，PD 两种传输路径的输出与单卡缓存一致。

首版同进程单请求串行，需为两卡各自预留权重与 KV 缓存空间。未测试 8B、长上下文或多请求吞吐，未进行性能基准或 sanitizer 测试。


## 四卡 PD-PP / PD-TP

在新增的 `5090:~/project/QWECPP` checkout 继续开发。物理卡 4、5 用于 Prefill，6、7 用于 Decode。四卡模式要求两组布局一致，PP 按同一切层边界、TP 按相同 KV head rank 交接。P2P 能力探测和 pinned host 回退仍由公共 transfer 管理。调试统计单列 KV 交接，TP 组内传输保留原字段。

Qwen3-0.6B 四卡专项与对应两卡 PP/TP 缓存基线对照，KV 交接前后最大及平均绝对误差均为 0，argmax 一致。两个 prompt token 的 payload 均为 458752 字节，PD-PP 为 56 次主机中转，PD-TP 为 112 次，P2P 均为 0。构建、4 项 CTest 和原单卡/PP/TP 缓存回归通过。构建使用 CUDA 13.2、SM 120，PCRE2 和 ICU 来自同一个 Conda 环境以匹配头文件和库。

复现命令（模型路径按机器调整）：

```bash
export CUDA_VISIBLE_DEVICES=4,5,6,7
build/bin/test_kv_cache ~/models/Qwen/Qwen3-0.6B pd-pp
build/bin/test_kv_cache ~/models/Qwen/Qwen3-0.6B pd-tp
python3 tests/models/test_kv_chat.py --four-gpu
```
PD-PP 和 PD-TP 的多轮聊天及 `/clear` 通过，输出与各自两卡缓存基线一致。
